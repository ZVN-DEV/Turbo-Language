Part 1

Language Reference

Complete syntax and semantics for every language feature.

Variables

Turbo is immutable by default. Use let for immutable bindings and let mut when you need to change a value. Types are inferred in most cases, but you can add annotations when they improve clarity.

Turbo
// Immutable by default
let name = "world"
let age: u32 = 25

// Mutable with `mut`
let mut counter = 0
counter += 1

// Constants (compile-time known)
const MAX_SIZE: usize = 1024
const PI: f64 = 3.14159265358979

Destructuring

Pull values out of objects and arrays directly at the binding site, just like JavaScript.

Turbo
// Object destructuring
let { name, age, ...rest } = user

// Array destructuring
let [first, second, ...tail] = items

// Nested destructuring with defaults
let { address: { city, zip }, role = "user" } = config

Functions

Functions are declared with fn. The last expression is the return value. Turbo supports default parameters, named arguments, closures, and both pipe-style and arrow-style lambdas.

Basic Functions
// Basic function — last expression is the return value
fn add(a: i32, b: i32) -> i32 {
  a + b
}

// Default parameters
fn greet(name: str, greeting: str = "Hello") -> str {
  "{greeting}, {name}!"
}

// Named arguments at call site
greet(name: "Alice", greeting: "Hi")

Arrow Functions and Closures

Arrow functions work like JavaScript. Pipe-style closures work like Rust. Both are interchangeable.

Closures
// Arrow functions (JS-style)
let double = (x) => x * 2
let add = (a, b) => a + b

// Pipe-style closures (Rust-style)
let double = |x| x * 2

// Multi-line with type annotations
let process = (data: [Record]) => {
  let cleaned = data.filter((d) => d.valid)
  cleaned.map((d) => d.value)
}

// In higher-order functions
let names = users
  .filter((u) => u.active)
  .map((u) => u.name)
  .sort_by((a, b) => a.cmp(b))

Async Functions

Async
async fn fetch_user(id: u64) -> User ! Error {
  let resp = await http.get("/users/{id}")?
  resp.json<User>()?
}

Compile-Time Computation

Functions marked const fn are evaluated at compile time when called in a const context. This enables type-safe code generation without macros.

const fn
const fn fibonacci(n: u64) -> u64 {
  match n {
    0 => 0
    1 => 1
    n => fibonacci(n - 1) + fibonacci(n - 2)
  }
}

// Computed at compile time — zero runtime cost
const FIB_20: u64 = fibonacci(20)

Optionals

Turbo has no null. Instead, values that may be absent use the T? optional type with none for the absent case and some(v) for the present case. Optional chaining (?.) and null coalescing (??) work exactly like JavaScript.

Turbo
// Optional type
let name: str? = some("Alice")
let missing: str? = none

// Optional chaining
let city = user?.address?.city      // str?

// Null coalescing — provide a default
let name = user?.name ?? "Anonymous"

// Chained method calls
let upper = user?.name?.to_upper() ?? "UNKNOWN"

// Pattern matching on optionals
match user?.address {
  some(addr) => print("Lives in {addr.city}")
  none => print("No address on file")
}

Error Handling

Functions that can fail return T ! E (a result that is either a value T or an error E). The ? operator propagates errors to the caller. Use match to handle results explicitly, or chain with with blocks for multiple fallible operations.

Result Type and Propagation
// Function that can fail
fn parse_int(s: str) -> i32 ! ParseError {
  // ...
}

// ? propagates errors to the caller
fn process(input: str) -> Output ! Error {
  let n = parse_int(input)?
  let data = fetch_data(n)?
  transform(data)
}

// Match on results
match parse_int("42") {
  ok(n) => print("Got {n}")
  err(e) => print("Error: {e}")
}

With Blocks

Chain multiple fallible operations with with blocks, inspired by Elixir.

Turbo
fn complex_operation() -> Data ! Error {
  with {
    let config = load_config()?
    let conn = connect(config.db_url)?
    let data = query(conn, "SELECT *")?
  } yield {
    transform(data)
  }
}

Pattern Matching

The match expression is exhaustive — the compiler ensures every case is covered. Turbo also supports if let for single-pattern checks, guard let for early returns, and pattern matching in function heads.

Match Expressions
// Match with guards
fn classify(n: i32) -> str {
  match n {
    0 => "zero"
    n if n > 0 => "positive"
    _ => "negative"
  }
}

// if let for single-pattern checks
if let ok(user) = fetch_user(id) {
  print("Found: {user.name}")
}

// guard let for early returns
guard let value = optional else { return }

// Pattern matching in function heads
fn factorial(0) -> u64 { 1 }
fn factorial(n: u64) -> u64 { n * factorial(n - 1) }

Destructuring in Match

Turbo
match response {
  ok({ status: 200, body }) => process(body)
  ok({ status: 404, .. }) => print("Not found")
  err(e) => print("Error: {e}")
}

Structs and Traits

Structs define data. Traits define behavior. Use impl to implement traits for structs. The @derive decorator auto-generates common trait implementations.

Structs
@derive(Debug, Eq, Serialize)
struct User {
  name: str
  email: str
  age: u32
}

// Instantiation
let user = User { name: "Alice", email: "alice@example.com", age: 30 }
Traits and Impl
// Define a trait (interface)
trait Drawable {
  fn draw(self, canvas: &Canvas)
  fn bounds(self) -> Rect

  // Default implementation
  fn is_visible(self) -> bool { true }
}

// Implement a trait for a type
impl Drawable for Circle {
  fn draw(self, canvas: &Canvas) {
    canvas.circle(self.center, self.radius)
  }
  fn bounds(self) -> Rect {
    Rect.from_center(self.center, self.radius * 2, self.radius * 2)
  }
}

Derive Macros

Common trait implementations can be auto-generated with @derive:

  • Debug — human-readable debug output
  • Eq, Hash — equality comparison and hashing
  • Serialize, Deserialize — JSON and other formats
  • Schema — auto-generate JSON Schema for structured LLM output

Enums / Algebraic Data Types

The type keyword defines algebraic data types (ADTs) with named variants. Each variant can carry different data. Combined with exhaustive pattern matching, ADTs eliminate entire categories of bugs.

Turbo
type Shape {
  Circle(radius: f64)
  Rectangle(width: f64, height: f64)
  Triangle(a: f64, b: f64, c: f64)
}

type HttpStatus {
  Ok
  NotFound
  ServerError(message: str)
}

// Type aliases
type UserId = u64
type Point = (f64, f64)

Generics

Write functions and types that work with any type using angle-bracket syntax. Constrain generic parameters with trait bounds.

Turbo
// Generic function
fn first<T>(items: [T]) -> T? {
  match items {
    [head, ..] => some(head)
    [] => none
  }
}

// With trait bounds
fn largest<T: Ord>(items: [T]) -> T? {
  items.reduce((a, b) => if a > b { a } else { b })
}

// Generic struct
struct Pair<A, B> {
  first: A
  second: B
}

Concurrency

Turbo offers a layered concurrency model: async/await for familiar async code, structured concurrency for safe parallelism, channels for communication, actors for isolated state, and compile-time data race prevention.

Async / Await

Works exactly like JavaScript. Future<T> is Turbo's version of Promise<T>. Top-level await works out of the box.

Async Basics
// Async function
async fn fetch_user(id: u64) -> User ! Error {
  let resp = await http.get("/users/{id}")?
  resp.json<User>()?
}

// Concurrent execution (like Promise.all)
let [users, posts, comments] = await all([
  fetch_users(),
  fetch_posts(),
  fetch_comments()
])

// Race (like Promise.race)
let fastest = await race([
  fetch_from_primary(),
  fetch_from_fallback()
])

Spawn and Structured Concurrency

Structured Concurrency
// Spawn a lightweight task
let handle = spawn async {
  await fetch_data(url)
}
let result = await handle

// Scoped concurrency — all tasks guaranteed done at scope end
async fn fetch_all(urls: [str]) -> [Data] ! Error {
  scope (s) => {
    let tasks = urls.map((url) => s.spawn(async { await fetch(url)? }))
    await tasks.collect()?
  }
}

Channels

Channels and Select
let (tx, rx) = channel<Message>(buffer: 32)

spawn async {
  for i in 0..100 {
    await tx.send(Message { id: i, data: compute(i) })
  }
}

// Receive from a channel
for await msg in rx {
  process(msg)
}

// Select across multiple channels
select {
  msg = rx1.recv() => handle_a(msg)
  msg = rx2.recv() => handle_b(msg)
  _ = timeout(5.seconds()) => fallback()
}

Actors

Isolated stateful processes with message passing and supervision trees, inspired by Erlang/OTP.

Actors
actor Counter {
  state: u64 = 0

  fn increment(self) {
    self.state += 1
  }

  fn get(self) -> u64 {
    self.state
  }

  fn on_error(self, error: Error) -> ActorAction {
    .restart(backoff: exponential(base: 100.ms))
  }
}

// Supervision tree
let supervisor = Supervisor.new(strategy: .one_for_one)
  .child(Counter.new())
  .child(Logger.new())
  .child(CacheActor.new())

Async Streams

Streams
// Produce a stream with yield
async fn token_stream(prompt: str) -> Stream<Token> {
  let response = await llm.complete(prompt)
  for await chunk in response.stream() {
    yield Token.parse(chunk)
  }
}

// Consume and transform streams
let upper = token_stream("Hello")
  |> map_stream((t) => t.text.to_upper())
  |> filter_stream((t) => !t.is_empty())

Agents: Sidecar, Not Core

Earlier drafts of this page documented agent and tool fn as core-language keywords. That direction has been retired. Agent and tool workflows will ship as a separate library, turbo-agent, built on top of the stable 1.0 core — not as compiler features.

The reasoning is simple: LLM tooling (providers, tool-calling schemas, memory strategies, supervision patterns) moves fast and changes shape every few months. A core language must not. If those decisions were baked into the grammar, every pivot in the AI ecosystem would break source compatibility across a whole fleet of Turbo programs.

What the core ships that makes a sidecar credible

  • Typed async — async fn, spawn, await, channels, mutex
  • HTTP client + server — enough to talk to any model provider's API
  • Typed serialization — JSON builtins and struct @derive attributes
  • Native compilation — JIT, AOT, and WASM output
  • Tooling integration — formatter, tests, playground, LSP

Roadmap

Ship Turbo core 1.0 with an explicit stability contract (see COMPATIBILITY.md). Then start turbo-agent as a separate repository with its own SemVer line, providing idiomatic building blocks — provider adapters, tool-calling schemas, streaming responses, conversation memory — as library types, not compiler keywords.

Modules

Turbo uses JavaScript-style import syntax. Items are private by default — use pub to export. Dependencies are managed via turbo.toml and the built-in package manager.

Imports
// Import specific items
import { HashMap, HashSet } from "std/collections"
import { Read, Write } from "std/io"

// Import a module
import http from "http"

// Aliased import
import { HashMap as Map } from "std/collections"
Visibility
// Public (exported)
pub fn public_function() { }
pub struct PublicStruct { }

// Private (default)
fn private_function() { }

Metaprogramming

Turbo takes a deliberately minimal approach to metaprogramming. Instead of a macro system, Turbo provides three mechanisms that cover 95% of use cases with zero magic: @derive, const fn, and generics with trait bounds. No proc macros, no preprocessor.

@derive — Automatic Trait Implementations

The @derive(...) decorator tells the compiler to auto-generate boilerplate implementations for common traits. This replaces Rust's procedural macros with a built-in, well-defined expansion that the compiler fully understands.

@derive
@derive(Debug, Eq, Hash, Clone, Serialize, Schema)
struct User { name: str, age: u32 }

// The compiler generates: Debug.fmt(), Eq.eq(), Hash.hash(),
// Clone.clone(), Serialize.serialize(), and a JSON Schema
// — all from the struct definition.

const fn — Compile-Time Computation

Any function marked const fn runs at compile time when called in a const context. This replaces traditional macro-based code generation with regular, debuggable, type-checked functions.

const fn
const fn generate_routes(prefix: str, names: [str]) -> [Route] {
  names.map((name) => Route { path: "{prefix}/{name}", handler: name })
}

// Evaluated entirely at compile time
const ROUTES = generate_routes("/api", ["users", "posts", "comments"])

What Turbo Does NOT Have

  • No Rust-style procedural macros (macro_rules!, proc_macro)
  • No C/C++ preprocessor (#define, #ifdef)
  • No Lisp-style code-as-data macros
  • No template metaprogramming

Philosophy: Prefer const fn + generics + @derive over macro systems. All code stays visible, type-checked, and IDE-friendly. Conditional compilation uses @cfg attributes, not preprocessor directives.

Batteries included. No external dependencies for common tasks.

Example: HTTP Server

main.tb
fn main() {
  let app = http_server(8080)

  route(app, "GET", "/", |req: str| -> str {
    respond(200, "Hello from Turbo!")
  })

  route(app, "POST", "/api/echo", |req: str| -> str {
    let body = request_body(req)
    respond(200, body)
  })

  http_listen(app)
}
