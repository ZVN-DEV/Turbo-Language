# E0516 — Compiler recursion limit exceeded

## What it means
The input contains an expression that is nested more deeply than the
compiler is willing to recurse into — either during parsing or during
code generation. The limit is fixed at 256 levels and is shared across
both stages so anything the parser accepts is something codegen can
also lower. Hitting the limit means the compiler refused to risk a
stack overflow on pathological or adversarially-deep input, and
returned a diagnostic instead.

## Example
```turbo
fn main() {
    // 300+ nested parens — rejected by the parser.
    let x = (((((((/* ... 256+ deep ... */ 1)))))))
    print(x)
}
```

A chained-unary tower (`!!!!!!...!true`) or a run-on assignment chain
(`a = b = c = ... = 1`) deep enough to exceed the limit can also
trigger this error.

## How to fix
Turbo source code almost never needs deep expression nesting. If you
hit this error in hand-written code, refactor the expression into
helper functions or intermediate `let` bindings:

```turbo
let inner = compute_inner()
let x = wrap(inner)
```

If you are generating Turbo source programmatically (e.g. from a
macro or a code generator), flatten the output into a sequence of
statements rather than a single deeply-nested expression. If you
genuinely need more than 256 levels of nesting, open an issue — the
limit is a constant (`MAX_PARSER_DEPTH` / `MAX_CODEGEN_DEPTH`) chosen
to protect the compiler from stack overflow on adversarial input, not
a language-level constraint.
